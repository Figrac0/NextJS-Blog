## 🚀 Обзор

**T-Guide** — это умный аудиогид и конструктор городских маршрутов. Пользователь открывает приложение и попадает на полноэкранную карту, видит точки интереса вокруг, слушает профессиональные аудиоистории о местах, собирает свой маршрут точка за точкой и проходит его с навигацией по GPS в реальном времени. Готовые кураторские маршруты — архитектурные прогулки, гастрономические туры, исторические маршруты — доступны прямо из каталога.

Проект собран как единый продукт сразу для трёх рантаймов:

- публичное web-приложение
- нативное Android-приложение, упакованное через Capacitor 8
- контейнерный деплой, опубликованный в GitHub Container Registry

Приложение намеренно построено вокруг реального городского исследования, а не CRUD-демо:

- полноэкранная карта с фильтрами по категориям и настраиваемым радиусом поиска
- drag-to-snap шторка с тремя позициями фиксации
- аудиогиды с полными транскриптами для доступности
- ручной конструктор маршрутов с drag-to-reorder остановками
- режим экскурсии с живым расстоянием и временем пешего хода до следующей точки
- каталог готовых маршрутов с темами, сложностью и рейтингами
- личный кабинет с сохранёнными маршрутами, личными маршрутами и историей прохождений
- полнофункциональная админ-панель для управления точками, категориями, экскурсиями и пользователями

## 🗺️ Карта открытий и шторка

Главный экран — это полноэкранная Leaflet-карта, и вся модель взаимодействия построена вокруг одной drag-to-snap шторки, которая живёт поверх неё. Шторка написана вручную — без библиотек — чтобы поведение snap, передача скролла и взаимодействие жестов с картой оставались полностью под контролем.

### Модель snap-позиций

У шторки три дискретных snap-позиции:

- **Closed** — виден только bar drag-handle (`52 px`)
- **Peek** — bar + 72 px draft-preview bar (`124 px`), включается автоматически, когда пользователь добавил первую точку в черновик
- **Full** — body полностью раскрыт и скроллится

Snap-таргеты пересчитываются при resize и при изменении количества точек в черновике, чтобы шторка оставалась согласованной при любых изменениях viewport:

```ts
const CLOSED_HEIGHT = 52             // только bar drag-handle
const INTERMEDIATE_PEEK_HEIGHT = 124 // bar + draft-preview bar
const SHEET_SNAP_EASING = 'cubic-bezier(0.25, 0.46, 0.45, 0.94)'
const SHEET_SNAP_DURATION_MS = 480
```

### Snap с учётом скорости жеста

При отпускании шторки следующая snap-цель выбирается по расстоянию и затем смещается по скорости pointer'а. Чем быстрее жест, тем короче анимация — чтобы отклик ощущался физично:

```ts
const durationMs = absV > 12
  ? SHEET_SNAP_FAST_DURATION_MS    // 300 ms
  : absV > 6
    ? SHEET_SNAP_MEDIUM_DURATION_MS // 400 ms
    : SHEET_SNAP_DURATION_MS        // 480 ms
```

### Координация жестов

Во время перетаскивания `pointer-events` карты отключаются, чтобы пользователь случайно не сдвинул карту, двигая шторку. Когда шторка полностью открыта и пользователь тянет вниз сверху скролла, шторка сворачивается, а не дёргает body — маленькая, но важная деталь для одноручного мобильного UX.

## 🎧 Слой аудиогида

Каждая точка интереса может содержать профессиональный аудио-трек и текст транскрипта. Слой воспроизведения намеренно минимален — он использует нативный `<audio>` браузера, без скрытых буферов, без service worker-трюков и без сторонних SDK.

Что UI добавляет поверх этого:

- кнопка воспроизведения, дёргающая нативный audio API
- лейблы длительности через `preload="metadata"`, чтобы UI показывал реальную длительность до нажатия Play
- явная индикация языка для каждого аудиогида
- раскрытие транскрипта с анимированной высотой, разбитого на параграфы
- автоматический сброс аудио при переходе на следующую остановку в экскурсии

Раскрытие транскрипта — то, что превращает аудио-слой из «приятного дополнения» в реально пригодный инструмент для людей с нарушениями слуха: тот же контент всегда доступен в виде читаемого текста.

## 🧭 Конструктор маршрутов и навигация через OSRM

Конструктор маршрутов — место, где сценарий открытий превращается в инструмент.

### Построение маршрута

На `/excursions` карта показывает ближайшие точки, а пользователь собирает маршрут, кликая по маркерам и нажимая **Добавить в маршрут**. Черновик отрисовывается на карте в реальном времени как нумерованная цепочка. Остановки можно менять местами перетаскиванием, общее количество ограничено 10 — лимит-бейдж заметно «дёргается» при попытке выйти за него.

Reorder остановок построен на pointer-driven hit-test цикле с passive-listener'ами, чтобы браузер мог свободно композитить во время движения:

```ts
const onMove = (e: PointerEvent) => {
  const items = [...container.children] as HTMLElement[]
  let bestIdx = 0, bestDist = Infinity
  for (let i = 0; i < items.length; i++) {
    const { top, height } = items[i].getBoundingClientRect()
    const mid = top + height / 2
    const d = Math.abs(e.clientY - mid)
    if (d < bestDist) { bestDist = d; bestIdx = i }
  }
  setReorderState(prev => prev && prev.overIdx !== bestIdx
    ? { ...prev, overIdx: bestIdx }
    : prev,
  )
}
```

### Геометрия маршрута через OSRM

Пешая геометрия между остановками строится через **OSRM** — это не наивная прямая линия, а реальный пеший путь по дорогам, отрисованный поверх Leaflet-карты.

### Режим экскурсии

После старта экскурсии приложение переключается в выделенный режим навигации:

- карта становится полноэкранной, на ней — текущая позиция и подсвеченная активная остановка
- расстояние до точки пересчитывается по живому GPS
- расчётное время пешего хода берётся при `~5 км/ч`
- карточка остановки показывает фото, расписание, рейтинг, описание и аудиогид
- кнопки **Предыдущая** и **Следующая** двигают между остановками, перецентрируют карту и сбрасывают аудио + транскрипт
- **Завершить** фиксирует экскурсию в истории пользователя с процентом прохождения

Именно это превращает T-Guide из приложения-«открытия» в полноценный гид-сценарий.

## 🔐 Аутентификация и админ-панель

### JWT-поток

Аутентификация использует пару access + refresh:

- регистрация по email и паролю
- вход возвращает access- и refresh-токены
- при `401` access-токен молча обновляется и **исходный запрос повторяется**
- защищённые маршруты редиректят на вход и возвращают пользователя на исходную страницу после авторизации
- смена пароля доступна из профиля, восстановление — по email

### Админ-панель

Админ-панель по адресу `/admin` — это реально работающая поверхность, а не заглушка. Она покрывает всю контентную модель приложения:

- **Точки** — создание / редактирование / удаление с пагинируемым поиском, полной метаинформацией, интерактивной админ-картой с геокодером **Nominatim** и загрузкой медиа (фото, аудио, видео) вместе с транскриптами и порядком сортировки
- **Категории** — создание / переименование / удаление с проверкой зависимостей перед удалением
- **Экскурсии** — авторинг кураторских маршрутов с подбором точек, их порядком и настройкой видимости (публичный / приватный)
- **Пользователи** — список с поиском и пагинацией, смена роли (user / admin), активация и блокировка аккаунтов

Админ-панель намеренно использует те же компонентные примитивы, что и публичное приложение, — поэтому редакторские сценарии и пользовательский UI развиваются вместе, а не расходятся.

## 📱 Android через Capacitor 8

T-Guide распространяется и как нативное Android-приложение — та же web-сборка обернута через **Capacitor 8** без форка кодовой базы. Все функции работают идентично web-версии.

Что добавляет нативная оболочка:

- **GPS** через системный `FusedLocationProvider` — быстрее и точнее, чем браузерный API
- **Edge-to-edge layout** — хедер заходит в зону статус-бара, жесты навигации не перекрывают контент
- **Нативный спиннер разрешений** через `requestPermissions` при первом запросе GPS

Сборка и запуск:

```bash
# 1. Собрать web-часть
npm run build

# 2. Синхронизировать в Android-проект
npx cap sync android

# 3. Открыть в Android Studio и запустить на устройстве или эмуляторе
npx cap open android
```

После `cap sync` все изменения из web-версии (UI, логика, стили) автоматически попадают в Android-приложение — отдельной ветки APK-кода поддерживать не нужно.

## 🏗️ Архитектура Feature-Sliced Design

Проект организован по методологии **Feature-Sliced Design (FSD)**, которая держит доменные слои изолированными и зависимости — однонаправленными.

```text
src/
├── app/        ← Точка входа, роутер, провайдеры (Auth, UserRoutes)
├── pages/      ← Home, Excursions, Excursion, Profile, Admin, SignIn
├── features/   ← Функциональные модули: Leaflet-карта, геолокация, пользовательские маршруты
├── entities/   ← Доменные модели: Excursion, NearbyPoint, RouteStop, data-хуки
├── widgets/    ← Составные блоки: ExcursionCatalog, RouteOverview
└── shared/     ← API-слой, утилиты, конфиги, токены, UI-компоненты
```

### Ключевые паттерны

- **Session-level кеш точек** — `/points/{id}` запрашивается не чаще одного раза за сессию, обогащается через `usePointDetailsMap` и переиспользуется на карте, в strip-черновике и в detail-панели
- **Drag-to-snap шторка** — собственная реализация на pointer events, одинаково работает на touch и mouse
- **Lazy loading** — каждая страница уровня роута грузится по требованию через `React.lazy`
- **Refresh-token flow** — прозрачное обновление JWT при `401` с повтором исходного запроса
- **Геометрия OSRM** — реальные пешие пути между остановками, а не прямые линии
- **Без CSS-in-JS** — дизайн-токены вынесены в CSS custom properties и применяются обычными стилями

Именно эта структура — причина, по которой проект с такой широкой поверхностью (открытия, навигация, аудио, админка, нативная оболочка) остаётся понятным файл за файлом.

## 🚀 Деплой, Docker и CI/CD

T-Guide задеплоен как единый Docker-образ, который публикуется в **GitHub Container Registry** при каждом пуше в `main`.

### Запуск из GHCR

```bash
docker pull ghcr.io/figrac0/t-guide:latest

docker run -d \
  --name t-guide \
  -p 3000:80 \
  --restart unless-stopped \
  ghcr.io/figrac0/t-guide:latest
```

### Сборка с кастомным API

```bash
docker build \
  --build-arg VITE_API_URL=https://your-api.example.com/api \
  --build-arg VITE_MAP_PROVIDER=osm \
  -t t-guide .
```

### Переменные окружения

| Переменная | Описание | Пример |
| --- | --- | --- |
| `VITE_API_URL` | URL бэкенда | `https://tguide.enzolu.ru/api` |
| `VITE_MAP_PROVIDER` | Провайдер тайлов карты | `osm` |
| `VITE_USE_MOCK_API` | Мок-режим (без бэкенда) | `false` |

### CI/CD

GitHub Actions автоматически собирает и публикует образ при каждом пуше в `main`:

```text
push → main
  └── Checkout
  └── Docker Buildx
  └── Login GHCR
  └── Build & Push → ghcr.io/figrac0/t-guide:latest
                   → ghcr.io/figrac0/t-guide:{sha}
```

Кеширование слоёв через GitHub Actions Cache (`type=gha`) ускоряет повторные сборки.

## 🎯 Чем проект выделяется

T-Guide соединяет слои, которые обычно показывают по отдельности, но редко собирают в один цельный продукт:

- полноэкранную Leaflet-карту открытий с фильтрами по категориям и настраиваемым радиусом
- собственноручно написанную drag-to-snap шторку со snap'ом по скорости и scroll-to-close
- реальный аудио-слой с транскриптами для доступности
- ручной конструктор маршрутов с drag-to-reorder, лимитом в 10 точек и пешей геометрией OSRM
- режим навигации с расстоянием и временем по живому GPS и сбросом аудио на каждой остановке
- кураторский каталог маршрутов с темами, сложностью и рейтингами
- JWT-аутентификацию с прозрачным refresh и возвратом на защищённый маршрут после входа
- полнофункциональную админ-панель для точек, категорий, экскурсий и пользователей
- нативную Android-оболочку через Capacitor 8 на той же web-сборке
- контейнерный релиз, опубликованный в GHCR при каждом пуше в `main`

Это не map-демо и не CRUD-админка. Это единый продукт, который проводит человека от «открыл приложение прямо на улице» до «прошёл аудио-маршрут по городу» — и поставляется в web, на Android и в виде Docker-образа из реестра из одной кодовой базы.
